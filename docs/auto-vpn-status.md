# Auto VPN: что сделано, что проверено и что осталось

## Что сделано

Форк v2rayNG получил режим, который реально запускает и полностью останавливает туннель в зависимости от приложения на экране.

- **Политики приложений:** «Через VPN», «Без VPN», «Всегда отключать VPN»; по умолчанию — «Без VPN».
- **Экран настроек** (Настройки → Расширенные настройки → «Автоматическое управление VPN»): объяснение и кнопка выдачи разрешения, переключатель режима, три категории, задержка отключения (Сразу / 5 / 10 / 20 / 30 с), «Не отключать VPN при выключенном экране», блок состояния.
- **Экран приложений:** иконки, поиск, фильтры «Все / Через VPN / Без VPN / Отключают VPN», выбор политики. Показываются только приложения, которые можно открыть.
- **Движок:** `UsageEvents` (опрос 500 мс только при разблокированном экране) → резолвер primary-приложения → чистый reducer решений → сериализованный контроллер команд → существующий жизненный цикл `CoreVpnService`/Xray.
- **Split-screen:** фокус между панелями Android не сообщает, поэтому действует безопасное правило — видимое «Всегда отключать VPN» выключает туннель, иначе видимое «Через VPN» его удерживает.
- **Восстановление:** при старте монитора и после разблокировки текущее приложение восстанавливается из истории `UsageEvents`; монитор поднимается после перезагрузки, обновления APK и убийства процесса.

### Дефекты, найденные только на эмуляторе и исправленные

1. **Settings распознавались как домашний экран.** У пакета `com.android.settings` есть служебная `FallbackHome` с категорией HOME (`priority=-1000`). Launcher теперь определяется по конкретной Activity с приоритетом ≥ 0, а не по пакету.
2. **Повторное выключение экрана останавливало VPN мгновенно.** При включении экрана не сбрасывался момент начала задержки. Расчёт вынесен в чистые функции движка и покрыт тестом.
3. **Монитор не видел уже открытое приложение** после перезагрузки или обновления APK. Добавлено восстановление из истории `UsageEvents` (окно 1 час, с учётом `DEVICE_SHUTDOWN/STARTUP`).
4. **Split-screen:** при закрытии панели оставшаяся не получала события, а Chrome + Clock гасили туннель при видимом Chrome. Добавлены отслеживание набора видимых Activity и правило видимых панелей.
5. **UX:** в списке были служебные RRO-оверлеи и сам v2rayNG; у «Без VPN» всегда было «Приложений: 0»; заголовок группы дублировал пункт; две строки не использовались.

## Не проверено (`Not run`)

1. **Физические устройства** Samsung / Xiaomi / Huawei: поведение OEM-менеджеров батареи. Эмулятор их не воспроизводит.
2. **Реальный расход батареи** (`batterystats`, Perfetto, сценарии A/B/C/D из ТЗ): на эмуляторе нет модели батареи, выполнен только замер CPU-времени.
3. **PiP:** в образе эмулятора нет приложения с picture-in-picture. Правило основано на том, что PiP-окно находится в `PAUSED`; на устройстве не проверено.
4. **Экран блокировки с PIN/паролем:** в эмуляторе блокировка не настроена (`locked=false`), проверено только выключение экрана.
5. **Instrumentation-тесты** не написаны; проверки выполнены скриптами `adb` + `uiautomator`.
6. **TalkBack и D-pad** (требование `ui/AGENTS.md`): не проверялись. Строки списка объединяют семантику (`«Chrome, Через VPN»` — видно в дереве доступности), но озвучивание не проверялось.
7. **HEV-библиотеки:** локальная сборка не содержит `libhev-socks5-tunnel.so` (нет NDK). С настройкой «Use Hev TUN» по умолчанию демон падает при старте VPN — это воспроизведено на эмуляторе. Все сценарии выше выполнены с выключенным «Use Hev TUN» (TUN обслуживает xray-core). Сборка CI с NDK эту проблему не имеет.

## Как повторить

```sh
adb install -r V2rayNG/app/build/outputs/apk/playstore/debug/v2rayNG_*_x86_64.apk
adb shell appops set com.v2ray.ang android:get_usage_stats allow   # или вручную в «Доступ к статистике использования»
# в приложении: Настройки → Log Level → debug, чтобы видеть события движка
adb logcat | grep "AutoVpn:"
adb shell dumpsys connectivity | grep "ni{VPN"
adb shell ip -o link | grep tun
```

## Известные ограничения

- **Фокус в split-screen не определяется.** Действует правило видимых панелей. Следствие: при видимых «Через VPN» и «Без VPN» туннель остаётся включённым, даже если пользователь работает во втором окне.
- **Задержка обнаружения ≈ 1 с** (запуск Activity + до 500 мс опроса + 250 мс стабилизации). Визит в «запрещённое» приложение короче этого может не выключить VPN.
- **Окно `STARTING`:** приложение может отправить прямой запрос до создания TUN; без Always-on VPN с lockdown или root это не устраняется.
- **Остаточные соединения:** уже установленные TCP/QUIC-сессии и DNS-кеш чужого приложения не откатываются.
- **После перезагрузки** монитор начинает работать только после доставки `BOOT_COMPLETED` (на эмуляторе ~13 с после загрузки).
- **Выключение режима не гасит уже работающий туннель** — он остаётся под ручным управлением.
- **OEM-ограничения:** менеджер батареи может убить монитор; восстановление — при следующем открытии v2rayNG или после перезагрузки.
- **`values-bqi-rIR`:** бахтиярского перевода нет, лежит английский текст с комментарием.
- **Режим работы:** автоматический старт только в режиме VPN; в режиме прокси и root экран показывает предупреждение, остановка работает во всех режимах.
