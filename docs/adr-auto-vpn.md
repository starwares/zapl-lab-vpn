# ADR: Auto VPN по активному приложению

- **Статус:** принят, вердикт `IMPLEMENT WITH LIMITATIONS`.
- **Контекст:** per-app routing оставляет TUN и `TRANSPORT_VPN` видимыми для приложения, даже если его трафик исключён. Нужен реальный start/stop туннеля, без root, Accessibility и UI automation, поверх форка v2rayNG.

## Решение

Конвейер из пяти компонентов, каждый со своей единственной ответственностью:

```
UsageEvents (ACTIVITY_RESUMED) + SCREEN_ON/OFF/USER_PRESENT
        │
        ▼
ForegroundAppMonitor        — только сбор сигналов, опрос 500 мс и только при «живом» экране
        │
        ▼
PrimaryForegroundAppResolver — фильтрация System UI / IME / диалогов, стабилизация 250 мс,
        │                      HOME-Activity → NO_ACTIVE_APP, набор видимых панелей
        ▼
AutoVpnPolicyEngine          — чистый reducer: START / STOP / STOP_IMMEDIATELY / KEEP
        │
        ▼
VpnLifecycleController       — единственный владелец команд, сериализация + generation
        │
        ▼
LauncherManager.startService() / MessageHelper(MSG_AUTO_VPN_STOP)
        │
        ▼
существующий жизненный цикл CoreVpnService и Xray
```

### Почему так

- **`UsageEvents`, а не Accessibility.** Accessibility требует декларации core functionality в Google Play, постоянно активного сервиса и даёт приложению доступ к содержимому чужих экранов. `PACKAGE_USAGE_STATS` даёт ровно то, что нужно, и включается пользователем на системном экране (AC-15).
- **Опрос 500 мс только при разблокированном экране.** Callback'а для `ACTIVITY_RESUMED` чужого приложения в Android нет. Корутина монитора висит на `StateFlow` состояния экрана, поэтому при выключенном экране wakeup'ов нет вообще. 50–100 мс запрещены заданием (п. 48).
- **Состояние туннеля читается у демона, а не запоминается.** `AutoVpnMonitorService` работает в процессе `:daemon`, поэтому `CoreServiceManager.isRunning()` — легальный источник истины по service-гайду. Ручной старт/стоп пользователем не рассинхронизирует движок.
- **Сериализация через conflated-канал.** Один worker выполняет команды по одной, а новое желаемое состояние вытесняет ещё не начатую команду. Это закрывает п. 15: нет двух start, двух stop, start во время stop и «опоздавших» команд.
- **Idle-таймер привязан к моменту ухода из VPN-приложения**, а не к последнему событию. Иначе навигация внутри «Без VPN» приложения бесконечно откладывала бы отключение.

### Политики

`VPN` (Через VPN) — старт сразу; `DIRECT` (Без VPN) — стоп по задержке отключения; `VPN_FORBIDDEN` (Всегда отключать VPN) — стоп немедленно, задержка не применяется. Значение по умолчанию — `DIRECT`, хранится только для явно настроенных пакетов.

## Последствия

- Работает без root, без Accessibility, без ADB/Shizuku; обычный режим v2rayNG не меняется, пока переключатель выключен (AC-19).
- Split-screen: проверено на эмуляторе, что смена фокуса между панелями не порождает событий `UsageEvents`, а обе Activity остаются `RESUMED`. Принято безопасное правило видимых панелей: видимое «Всегда отключать VPN» выключает туннель, иначе видимое «Через VPN» его удерживает. AC-10 выполнен в форме fallback-правила; focused pane не определяется.
- PiP: PiP-окно находится в `PAUSED` и не входит в набор видимых панелей, поэтому не удерживает VPN.
- Launcher определяется по HOME-Activity с `priority ≥ 0`, а не по пакету: пакет системных Settings содержит служебную `FallbackHome`.
- При старте монитора и после разблокировки набор видимых Activity восстанавливается из часовой истории `UsageEvents`, иначе уже открытое приложение оставалось бы незамеченным.
- Прямая утечка в окне `STARTING` и остаточные TCP/QUIC/DNS-кеши после stop без system lockdown/root не устраняются — см. `auto-vpn-detection-research.md`.
- Монитор требует Usage Access и может быть остановлен OEM-менеджером батареи (Xiaomi autostart, Huawei background launch).

## Отклонённые варианты

| Вариант | Почему нет |
|---|---|
| AccessibilityService | Политика Google Play, приватность, постоянно активный сервис; не доказана необходимость |
| `ActivityManager.getRunningTasks` | С Android 5 не возвращает чужой top task |
| Опрос 50–100 мс | Прямо запрещён заданием, дорог по wakeup'ам |
| Отдельное приложение, управляющее v2rayNG через Accessibility/ADB/Shizuku | Запрещено заданием (п. 48) |
| Изменение Xray core | Не требуется: жизненный цикл целиком на стороне Android |
| Обычный per-app proxy | Не скрывает факт наличия VPN, задача не решается |
