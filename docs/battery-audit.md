# Энергопотребление: замеры и находки

Дата: 2026-09-13. Ревизия: `7754140` (ветка `feature/ui-minimal-trust`, debug-сборка Play Store).

## Метод

- Эмулятор Pixel 9, Android API 37, x86_64; батарея переведена в режим «от батареи»
  (`dumpsys battery unplug`), `batterystats` сбрасывается перед каждым окном.
- CPU каждого процесса приложения (`store.zapl.lab.vpn`, `:daemon`) — разница
  `utime + stime` из `/proc/<pid>/stat` (через `run-as`) за окно 120–165 с.
- Wakelock, foreground services, CPU по uid — `dumpsys batterystats store.zapl.lab.vpn`.
- Фоновые сетевые соединения ядра — локальный логирующий SOCKS5-сервер на хосте
  (`adb reverse`), профиль `Local SOCKS`.
- Лёгкий трафик — HTTP-запрос из shell через VPN каждые 5 с.
- Обновления уведомления — смена `android.text` в `dumpsys notification` раз в 3 с.
- TCP keepalive — `ss -tnoi` на устройстве.

Ограничения: у эмулятора нет модели питания и сотового радио, поэтому оцениваются CPU,
wakelock и сетевые пробуждения, а не мА·ч. Отрисовка идёт через SwiftShader (CPU), поэтому
стоимость кадров сильно завышена по сравнению с устройством с GPU. Работа `system_server`
и SystemUI, выполняемая по запросам приложения, в CPU приложения не входит.

## Находки

### P1. Цикл скорости перезапускается при выключенном экране — подтверждено

`CoreServiceManager.launchCore()` в конце безусловно вызывает
`NotificationManager.startSpeedNotification()` (`core/CoreServiceManager.kt:191`), в том числе
из `reloadCore()` после смены сети (`NetworkMonitor`) и при старте без экрана (always-on,
перезапуск сервиса, Auto VPN). Остановка цикла выполняется только по `ACTION_SCREEN_OFF`
(`CoreServiceManager.kt:519-523`), поэтому после такого старта цикл работает до следующего
выключения экрана.

Замер S6 против S5: 50 обновлений уведомления за 150 с, 10,2 с partial wakelock в
`NotificationManagerService` от имени приложения (≈6,8 % времени), CPU `:daemon` +64 %; плюс
перерисовка уведомления в SystemUI. Касается только включённой настройки «Показывать скорость»
(по умолчанию выключена).

Исправление: в `startSpeedNotification()` не запускать цикл, если
`PowerManager.isInteractive == false` (запуск по `ACTION_SCREEN_ON` уже есть). Риск низкий.

### P2. Каждая разблокировка в Auto VPN — полный перезапуск ядра — подтверждено

При настройках по умолчанию (задержка 10 с, «Не отключать VPN при выключенном экране» выкл.)
туннель останавливается через 10 с после блокировки и полностью поднимается при
разблокировке, если на экране приложение «через VPN». Замер S10b: ≈385 мс CPU на цикл
(сборка конфига, резолв сервера, старт Xray с geo-файлами, `establish()`), плюс переподключение
всех приложений и новые TLS-рукопожатия к серверу.

Варианты: увеличить задержку по умолчанию (60–120 с); гистерезис — не останавливать туннель,
если экран выключался меньше N минут; сделать «Не отключать VPN при выключенном экране»
значением по умолчанию. Это продуктовое решение: туннель живёт дольше.

### P3. TCP keepalive ≈45 с на долгоживущих соединениях ядра — измерено, влияние на радио не проверено

`ss -tnoi`: у постоянного исходящего соединения ядра (DoT к `1.1.1.1:853`) таймер keepalive
перезапускается каждые ≈45 с. `sockopt.tcpKeepAliveIdle/Interval` в конфиге не задаются
(`dto/V2rayConfig.kt`), используется значение по умолчанию ядра/Go. На сотовой сети каждая проба
поднимает радиомодуль из idle; при нескольких постоянных соединениях (DNS, push через туннель)
это может быть заметный вклад в расход при выключенном экране.

Предложение: задать `sockopt.tcpKeepAliveIdle`/`tcpKeepAliveInterval` (например, 300/60 с) для
proxy- и direct-outbound; проверить на устройстве с SIM (Battery Historian, `tcpdump`), что
соединения не рвутся по NAT-таймауту оператора. Риск средний.

### P4. Observatory для policy-групп — по коду, не замерено

Для групп leastPing/random/roundRobin включается `observatory` с `probeInterval` 3 мин и
`enableConcurrency = true` (`core/CoreConfigManager.kt:416-421`, `:1252-1260`,
`AppConfig.kt:145`): HTTPS-проба через каждого участника группы каждые 3 мин, круглосуточно,
в том числе при выключенном экране. Для leastLoad — `burstObservatory` раз в 5 мин.
Касается только пользователей policy-групп.

Предложение: значения по умолчанию 10/15 мин; для random/roundRobin не включать observatory без
явно заданного fallback. Риск: медленнее уход с мёртвого сервера.

### P5. Смена сети = полный reload ядра

`NetworkMonitor` на каждый `onAvailable` новой сети через 1 с вызывает `stopLoop()` +
`launchCore()` (`service/NetworkMonitor.kt:105-118`, `core/CoreServiceManager.kt:266-291`).
Стоимость близка к старту ядра (S7b/S10b: 120–385 мс CPU) плюс переподключения; при «мигающем»
Wi-Fi повторяется многократно. Предложение: не чаще одного reload в 10–30 с с отложенным
последним. Риск: мёртвые сокеты живут дольше при быстрых переключениях.

### P6. Автотест серверов после фонового обновления подписок — по коду

`SubscriptionUpdater` планирует periodic work только с ограничением `CONNECTED`
(`handler/SubscriptionUpdater.kt:136-145`); при включённом автотесте после обновления
проверяются все серверы с параллелизмом 16. Работает на сотовой сети и при низком заряде.
Предложение: `setRequiresBatteryNotLow(true)`, автотест только на unmetered-сети.

### P7. Auto VPN: опрос 500 мс и постоянный `:daemon` — низкий приоритет

При включённом экране монитор тратит 190 мс CPU за 150 с (S8) плюс работу `system_server`; при
выключенном экране опрос на паузе (S9: 60 мс за 150 с — фоновая жизнь процесса с Go runtime).
Возможное улучшение: адаптивный интервал (500 мс в течение нескольких секунд после события,
затем 1,5–2 с), фильтр типов событий на API 35+.

## Не проблема (проверено)

- WakeLock, WifiLock, AlarmManager, exact alarms, `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` в коде
  нет.
- VPN в покое почти бесплатен для CPU: 0,02–0,05 % ядра (S2, S3); собственных фоновых соединений
  ядро в покое не открывает.
- Цикл скорости не запускается при выключенной настройке и корректно останавливается при
  выключении экрана (S5), кроме случая P1.
- Главный экран в покое не рисует кадров (0 кадров за 10 с), бесконечных анимаций нет; кадры
  появляются только на действия пользователя (≈1 с анимаций на старт/стоп).
- Опрос Auto VPN не выполняется при выключенном или заблокированном экране (S9).

## Решения и статус

Принцип: VPN нужен, пока телефоном пользуются; экономия внедряется только там, где она не
ухудшает UX.

| Находка | Решение | Статус |
|---|---|---|
| P1 цикл скорости при выключенном экране | Не запускать цикл, если `PowerManager.isInteractive == false`; `ACTION_SCREEN_ON` запускает его как раньше. Решение вынесено в `shouldStartSpeedNotification()`, цикл живёт в хранимом scope `NotificationManager` | **Исправлено** |
| P2 Auto VPN при выключенном экране | Оставить: туннель не нужен при выключенном экране, текущая задержка 10 с уже покрывает короткие блокировки | Без изменений (продуктовое решение) |
| P3 TCP keepalive | Не менять без проверки на устройстве с SIM: риск разрыва простаивающих соединений NAT-ом оператора и задержки push | Отложено |
| P4 интервалы observatory | Не менять: мёртвый сервер обнаруживался бы дольше | Отклонено (UX) |
| P5 rate-limit reload | Не менять: мёртвые сокеты жили бы дольше после быстрой смены сети | Отклонено (UX) |
| P6 фоновое обновление подписок | `setRequiresBatteryNotLow(true)`: при низком заряде фоновое обновление (и автотест после него) ждёт; ручное обновление работает | **Исправлено** |
| P7 интервал опроса Auto VPN | Не менять: VPN включался бы позже при открытии приложения | Отклонено (UX) |

### Проверка исправлений

- JVM: `SpeedNotificationDecisionTest` — 5 тестов (выключено, цикл уже запущен, экран выключен
  после reload, ядро остановлено, успешный старт; ленивость проверок). Полный
  `:app:testPlaystoreDebugUnitTest` — 137 тестов, 0 падений; `assemblePlaystoreDebug`,
  `assembleFdroidDebug`, `assemblePlaystoreRelease`, `assembleFdroidRelease` (lintVital) —
  успешно.
- Эмулятор, режим VPN:
  - экран выкл. → смена сети (reload) → 30 с: текст уведомления не меняется; 150 с: 0 wakelock
    `NotificationManagerService:post` (до исправления — 50 обновлений и 10,2 с), CPU `:daemon`
    160 мс (до — 230 мс);
  - экран вкл. → смена сети: reload выполнен (новые соединения ядра), скорость обновляется;
  - экран выкл. → вкл.: цикл возобновляется, в том числе на экране блокировки;
  - остановка сервиса во время отложенного reload: VPN, уведомление и сервис сняты, падений нет;
    повторный старт работает.
- Эмулятор, режим proxy-only: те же сценарии (экран вкл./выкл., смена сети при обоих состояниях
  экрана, остановка во время отложенного reload) — результат совпадает с режимом VPN.
- P6: у задачи `SubscriptionUpdater$UpdateTask` в `JobScheduler` —
  `Required constraints: BATTERY_NOT_LOW … CONNECTIVITY`; при `dumpsys battery set level 5`
  ограничение становится невыполненным, после сброса — выполненным.
- Not run: root-режим (образ эмулятора без root), физическое устройство.

## Исходный приоритет исправлений

1. P1 — одна проверка `isInteractive`; подтверждённый фоновый расход при включённой скорости.
2. P2 — значения по умолчанию Auto VPN (задержка/гистерезис) — после продуктового решения.
3. P3 — keepalive в `sockopt`; обязательно проверить на устройстве с SIM.
4. P4 и P5 — интервалы observatory и rate-limit reload.
5. P6, P7.

## Not run

- Физическое устройство с SIM-картой: реальный мА·ч, пробуждения радиомодуля (P3), Doze,
  OEM-менеджеры батареи.
- Battery Historian, `tcpdump` на стороне сервера.
- P4 (policy-группы), P6 (автотест подписок) — только анализ кода.
- Root-режим и proxy-only режим.
